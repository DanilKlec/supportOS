## Исправление deployment blocker — лимит функций Hobby

После security-обновления Vercel успешно собрал commit `c188232`, но отклонил
deployment: в `api/` было 14 entry points при лимите 12 из deployment log.
Четыре AI wrapper-файла заменены одним `api/ai/[endpoint].js`: теперь **11**.
Существующие URL `/api/ai/status`, `/api/ai/generate`, `/api/ai/knowledge` и
`/api/ai/glossary` сохранены. Другие 10 entry points не менялись.

Dispatcher `server/ai/index.js` выбирает обработчик только по URL path и
передаёт исходные request/response без изменения body, query, headers или method.
Неизвестные пути возвращают 404; query/body не могут выбрать другой обработчик.
Auth, session checks, Telegram, RBAC, CSRF, optimistic conflicts и AI preflight
остаются внутри существующих handlers. Новых зависимостей, изменений БД,
frontend или vercel.json нет. В соответствии с
[Node.js runtime Vercel](https://vercel.com/docs/functions/runtimes/node-js)
deployment wrappers остаются в `api/`, реализации — вне этой директории.

Проверки после объединения:

- Целевые routing/auth/session tests: 50/50.
- Полный `npm run test`: 675/675, 119 files.
- `npm run check` и `tsc --noEmit`: PASS; прежние 61 warnings / 27 infos.
- `npm run test:visual`: 36/36, desktop/mobile, без обновления эталонов.
- `npm run build` и `git diff --check`: PASS; frontend chunks не изменились.
- Новый regression test проверяет полный список 11 deployment entry points.

Удалены только четыре тонкие обёртки `api/ai/{generate,glossary,knowledge,status}.js`;
бизнес-обработчики `server/ai/*.js` не удалялись. Обёртки восстановимы из Git.
Для следующего deployment нужно опубликовать и новые файлы, и эти удаления.
Удалённый Vercel deployment этим проходом не запускался: финальная проверка
packaging/routing на платформе остаётся за следующим пользовательским deploy.

`server/ai/index.js`, `server/ai/index.test.js`, `server/ai/entry-security.test.js`,

## Что падало и что исправлено

1. **Production storage:** `/api/content?dataset=bonuses&scope=shared` возвращал 502; normalized storage и revisions отсутствовали. Бинды существовали, но не имели category/folder структуры в БД. После репетиции на PGlite применены согласованные schema/backfill/mapping миграции. Пользователь подтвердил: бинды, почты и бонусы появились.
2. **Ложная диагностика:** generic DB helper для любого storage failure предлагал `agent-monitor.sql`, хотя monitor schema уже существовала. Теперь ошибка различает missing table, permissions/config и остальные ошибки; raw DB details не выдаются.
3. **Transition read regression:** missing normalized table не обрабатывалась. Read-only fallback разрешён только для подтверждённого PGRST205/404 и отсутствующей primary normalized data. Existing normalized rows всегда authoritative; permissions, network/5xx и missing dependencies не маскируются fallback. Legacy writes не добавлены.
4. **Vercel-only routing gap:** добавлены entry points для существующих authenticated `/api/projects` и `/api/ai/glossary`. Новые бизнес-функции не создавались. Эти локальные изменения ещё требуют redeploy/проверки preview.
5. **TypeScript:** исправлены три `useRef` initial values, unsupported/unused `Tabs.style` в AccountsPanel и обращения к отсутствующим risk/confidence props в QC test. Tabs не получил новую функциональность; исходный UI сохранён.
6. **Sports market reset:** опция «Все рынки» получала значение `A` вместо `All` из-за индексирования строки. Исправлена форма option tuple; добавлен regression test.
7. **Responsive QC playground:** длинное имя проекта растягивало implicit grid до 1024px на viewport 390px. Добавлены zero-min grid tracks и `min-w-0` детям; аналогично защищена grid формы AI знаний/тестов. CSS colors/tokens и layout intent сохранены, global overflow hiding не добавлен. В существующий responsive Playwright test добавлены playground, tests и project instructions.
8. **Русские labels:** исправлены отображаемые тексты архива, избранного, недавних, bind/category prompt, health page/report, языка/темы Settings и generic sports errors. Internal enums, codes и storage keys не менялись. Settings test проверяет русские подписи и сохранение `light`/`dark`/`en`.
9. **Check/lint:** исходно проверялись generated Playwright report files и выдавались тысячи нерелевантных ошибок. Includes ограничены исходным root, generated output исключён.
