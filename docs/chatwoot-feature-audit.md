# Проверка чата SupportOS

SupportOS использует Chatwoot для хранения диалогов, работы каналов и доставки сообщений. Права сотрудника определяет его аккаунт SupportOS и, для оператора, доступ к источнику в Chatwoot. Публичная настройка виджета возвращает только данные, нужные для установки виджета.

## Роли

| Возможность | Support | QC | Admin | Creator |
| --- | --- | --- | --- | --- |
| Свои диалоги, очередь и архив | Свои назначения и очередь доступных проектов | Все диалоги для проверки, свои для работы | Все | Все |
| Ответы, вложения, теги, назначение, статус, приоритет, блокировка игрока | В своих диалогах | В своих диалогах | Во всех диалогах | Во всех диалогах |
| Внутренняя заметка в чужом диалоге | — | Да | Да | Да |
| Наблюдение и адресные подсказки назначенному агенту | Получает адресованные ему подсказки | Да | Да | Да |
| Панель руководителя, загрузка и SLA | — | Да | Да | Да |
| Лимиты, смены, навыки и цели SLA | — | Да | Да | Да |
| Команды, участники, теги, поля и настройки веб-источников | — | — | Да | Да |
| Секрет подписи вебхука и удаление источников | — | — | — | Да |

Взятие диалога из очереди доступно связанной с Chatwoot учётной записи с доступом к этому источнику. Предпросмотр сохраняет права на чтение. Очередь и её счётчик охватывают все доступные оператору проекты. Фильтр сужает очередь до выбранного проекта. Роль Shift сохраняет обзор при наличии `monitor.read`.

## Покрытие сценариев Chatwoot

| Область | Уже в SupportOS | Остаётся для паритета |
| --- | --- | --- |
| Работа с диалогом | Публичный ответ, заметка, вложения, бинды, черновики в текущей сессии, закреплённые теги, поиск с раскладкой и опечатками, назначение, статусы, приоритет, до четырёх окон и групповые операции | Участники и @упоминания, полная работа с непрочитанными, индикатор набора, синхронизация черновиков между устройствами, макросы |
| Игрок и история | Карточка, справочник контактов, объединение дублей, доступная история, поля, блокировка, проект, IP при наличии, логин и ссылка на CRM заданного проекта | Запрос данных из CRM после подключения интеграции |
| Очередь | Атомарные лимиты, фильтр по проекту, смены, навыки, фоновое присутствие, перераспределение при обрыве связи, личное событие назначения и резервная серверная проверка | Подключение подписанного вебхука в рабочей среде, сквозной замер доставки и системного уведомления |
| Администрирование | Веб-источники и настройки виджета, команды и отдельные операторы на источниках, теги, поля, лимиты SupportOS и доступные политики Chatwoot | Каналы помимо сайтов, автоматизации, рабочее время источников, полный журнал действий |
| Руководитель | Активная таблица, наблюдение с приватными подсказками, текущая очередь, активность сайтов, загрузка и SLA по проектам | Исторические отчёты, CSAT и уведомления об эскалациях |

Для нативной атрибуции ответа, имени и фото сервер проверяет личный доступ оператора к профилю Chatwoot. Пилот через Platform API требует версии Chatwoot с проверкой прав приложения на профиль. Для штатного подключения вебхука требуется роль Creator в SupportOS. Адресные подсказки хранятся в SupportOS и видны автору и получателю.

Локальные сценарии используют синтетические аккаунты и диалоги. `node scripts/check-chatwoot-access.mjs` проверяет права Support, QC, Admin и Creator, включая очередь агента на двух доступных ему проектах. `node scripts/check-chatwoot-routing-load.mjs` проверяет лимиты, конкурирующие назначения и сохранение очереди при всплеске из 1 740 чатов на 50 агентов. Эти проверки воспроизводят серверную логику и не измеряют задержку рабочего Chatwoot.
