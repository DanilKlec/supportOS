# Общие данные команды

В «Общая база» откройте «Загрузить базовые бинды для всей команды». Выберите JSON или вставьте ссылку Google Sheets, проверьте список и нажмите «Опубликовать». JSON поддерживает массив биндов, объект `binds` и полный экспорт SupportOS с `knowledge.binds`. У каждого бинда нужны `slug` и `translations` с `language`, `title`, `content`; `tags` необязателен. Таблица использует колонки: название, RU, EN, DE, PT, EL. Доступ к таблице должен позволять приложению прочитать её.

Совпадения по ID или slug обновляют общий оригинал. Личные версии сотрудников сохраняются. Импорт выполняется целиком, до 1000 биндов и 3 МБ; конфликт требует повторного предпросмотра.

Почты проектов, депозитные бонусы и Bonus Tools имеют отдельные общие версии в Supabase. Редактирование создаёт черновик; «Сохранить для всех» публикует его. Опубликованные данные перечитываются при открытии раздела, возвращении в окно и каждые 30 секунд. Открытый черновик не перезаписывается; он сохраняется при переходах между разделами до перезагрузки приложения. Кнопка загрузки общей версии отменяет черновик с подтверждением.

При первой публикации администратор может нажать «Взять сохранённые данные браузера», проверить их и сохранить для всех. Старые локальные данные автоматически не публикуются. Пустой справочник у читателей означает, что администратор ещё не опубликовал данные.

Право `projects.write` по умолчанию у Admin и Creator. Support читает почты через `projects.read`, но не меняет их. Публикация бонусов и Bonus Tools требует `bonuses.write`, общих биндов — `knowledge.write`. Права проверяются сервером и повторно в транзакции БД. Публикации фиксируются в журнале доступа, версии защищают от одновременного перезаписывания.

Миграция `supabase/shared-content.sql` включена в `supabase/schema.sql`. API `/api/content` использует существующие серверные переменные Supabase. В проекте 11 Vercel Functions, включая новый обработчик. Для появления интерфейса нужен новый деплой приложения.


## Рабочее пространство и личные версии

Главная страница `/` — пространство биндов. Общие ответы доступны прямо в дереве «Бинды команды»; переключение «Версия команды / Моя версия» и персональное редактирование находятся в открытом бинде. Облачные записи отделены от локального редактируемого снимка базы. При переходе в справочники открытые вкладки остаются в памяти; кнопка «В бинды» возвращает в пространство.

Раздел `/shared-binds` теперь является центром управления общей базой и требует `knowledge.write`. Support не видит его в меню и не получает доступ по прямой ссылке. Вкладки общих почт и бонусов дополнительно проверяют `projects.write` и `bonuses.write`.

Обычные страницы почт, бонусов и калькуляторов не содержат импорта и публикации общих данных. Почты доступны только для чтения. В бонусах и калькуляторах можно сохранить личный снимок справочника через «Сохранить для себя»: он хранится в Supabase отдельно для каждого аккаунта и не меняет версию команды. «Сбросить мои изменения» удаляет личный снимок и возвращает актуальные данные команды. Опубликованные командные обновления не перезаписывают личный снимок.

Таблица `supportos_personal_content` и RPC добавляются миграцией `supabase/personal-content.sql` (также включена в общий schema.sql). Доступ выполняется через существующую `/api/content`; пользователя определяет проверенная сессия сервера. Количество Vercel Functions остаётся 11.

## Ветки и обмен биндом

В самом бинде выбирается Основная, Моя или адресованная пользователю ветка коллеги. Выбор сохраняется на сервере для каждого бинда. Моя наследует основную до первого сохранения. Сравнение и история позволяют взять старый текст за основу своей версии.

Чтобы поделиться, сохраните личную версию, нажмите «Поделиться моей веткой» и введите почту зарегистрированного сотрудника. Получатель видит живые обновления, может скопировать текст в свою ветку; менять оригинал автора нельзя. Отзыв убирает доступ после обновления данных (опрос каждые 30 секунд), но не удаляет уже сделанные копии. Сброс личной ветки также отзывает её адресные доступы.

Кнопка «Предложить мою версию команде» создаёт снимок на проверку. Редакторы с knowledge.write рассматривают его в Общая база → Предложения. Если основная успела измениться, публикация блокируется: нужно отозвать старое предложение и отправить новое после сравнения. История в рабочем бинде показывает только основную и собственную ветки. Миграция: supabase/bind-branches.sql.
