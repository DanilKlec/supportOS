# Общие данные команды

В «Общая база» откройте «Загрузить базовые бинды для всей команды». Выберите JSON или вставьте ссылку Google Sheets, проверьте список и нажмите «Опубликовать». JSON поддерживает массив биндов, объект `binds` и полный экспорт SupportOS с `knowledge.binds`. У каждого бинда нужны `slug` и `translations` с `language`, `title`, `content`; `tags` необязателен. Таблица использует колонки: название, RU, EN, DE, PT, EL. Доступ к таблице должен позволять приложению прочитать её.

Совпадения по ID или slug обновляют общий оригинал. Личные версии сотрудников сохраняются. Импорт выполняется целиком, до 1000 биндов и 3 МБ; конфликт требует повторного предпросмотра.

Почты проектов, депозитные бонусы и Bonus Tools имеют отдельные общие версии в Supabase. Редактирование создаёт черновик; «Сохранить для всех» публикует его. Опубликованные данные перечитываются при открытии раздела, возвращении в окно и каждые 30 секунд. Открытый черновик не перезаписывается; он сохраняется при переходах между разделами до перезагрузки приложения. Кнопка загрузки общей версии отменяет черновик с подтверждением.

При первой публикации администратор может нажать «Взять сохранённые данные браузера», проверить их и сохранить для всех. Старые локальные данные автоматически не публикуются. Пустой справочник у читателей означает, что администратор ещё не опубликовал данные.

Право `projects.write` по умолчанию у Admin и Creator. Support читает почты через `projects.read`, но не меняет их. Публикация бонусов и Bonus Tools требует `bonuses.write`, общих биндов — `knowledge.write`. Права проверяются сервером и повторно в транзакции БД. Публикации фиксируются в журнале доступа, версии защищают от одновременного перезаписывания.

Миграция `supabase/shared-content.sql` включена в `supabase/schema.sql`. API `/api/content` использует существующие серверные переменные Supabase. В проекте 11 Vercel Functions, включая новый обработчик. Для появления интерфейса нужен новый деплой приложения.
