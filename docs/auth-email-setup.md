# Собственная отправка писем SupportOS

Статус: шаблон подготовлен; внешний SMTP пока не подключён.

Используем Custom SMTP в Supabase Auth. Приложение продолжает вызывать `signUp`; Supabase создаёт и проверяет ссылки подтверждения, а доставку выполняет выбранный почтовый сервис. Новые аккаунты сохраняют статус pending до одобрения администратором. Дополнительный endpoint регистрации не требуется.

## Что нужно для подключения

1. Домен отправителя и доступ к его DNS.
2. Аккаунт в почтовом сервисе с поддержкой SMTP.
3. Подтверждение домена: добавить DNS-записи, которые выдаст сервис, и дождаться проверки. Значения SPF/DKIM берутся у выбранного сервиса, не из примеров.
4. SMTP host, port, username и password ввести непосредственно в защищённые настройки Supabase Authentication → Email → SMTP Settings. Не помещать секреты в VITE-переменные или Git.
5. Указать адрес отправителя на подтверждённом домене и имя SupportOS. Сохранить подтверждение email включённым.
6. Проверить Site URL и разрешённый Redirect URL приложения (`/login`), а также лимит отправки Auth с учётом ограничений провайдера.
7. В шаблоне Confirm signup установить тему «Подтвердите почту — SupportOS» и HTML из `supabase/templates/confirmation.html`. Сохранить `{{ .ConfirmationURL }}` без замены на обычный URL приложения.

## Проверка после подключения

Зарегистрировать согласованный тестовый адрес, проверить доставку письма и ссылку. До одобрения должен отображаться экран ожидания без рабочих прав. Затем администратор выбирает роли и одобряет заявку; пользователь получает только назначенные права. Проверить отсутствие доступа к QC у Support. Не запускать многократные регистрации при ошибке лимита.

Документация: https://supabase.com/docs/guides/auth/auth-smtp
